# heritages

[国指定文化財等データベース](https://kunishitei.bunka.go.jp/bsys/index) (文化庁) から
取り出した建造物・記念物のデータを、地図と一覧で見るサイト。**非公式**です。

データそのものは種別ごとの別リポジトリにあり
([code4heritage](https://github.com/code4heritage))、このリポジトリは**サイトだけ**を
持ちます。取得しているのはクローラー
([shinyaoguri/heritage-crawler](https://github.com/shinyaoguri/heritage-crawler))
で、決定ログ (ADR) とロードマップもそちらが正本です。

種別横断のサイトを 1 つだけ置いています。種別ごとに分けるのはデータであって
コードではなく、**同じ棟が複数の種別に現れる複合指定**が 114 件あるためです
(ADR 0015)。

## 作り

```
site/     配る静的ファイル (バンドラなしの素の ESM)
site/vendor/  同梱した地図ライブラリ (CDN から読まない。ADR 0016)
src/      配信ディレクトリを組み立てるビルド (Python 標準ライブラリのみ)
scripts/  データリポジトリの取得と、PR タイトルの検査
```

ビルドがすることは 3 つだけです。

1. データリポジトリの `meta.json` を束ねた `index.json` を書く
2. 一覧・検索・地図が読む行の索引 `records.json` を書く
3. `data/*.jsonl` を**変換せずそのまま**並べ、静的ファイルを重ねる

**JSON Lines に手を入れません。**サイトが見せているのはデータリポジトリのあの行
そのもの、と言える状態を保ちます。生成するのは索引だけです。

**データセットはリポジトリ名の表ではなく `meta.json` の有無で見つけます。**
種別が増えても減っても、サイト側に変更は要りません。

### 行の索引 (`records.json`)

2 万を超える行を扱うので、行はオブジェクトではなく配列で書きます (キー名の
繰り返しがそのまま転送量になる)。列の並びは `fields`、ファセットの語彙は `axes`
が持ちます。**索引は 1 本だけです** — 地図用の索引を別に持つと、名称とキーを
二重に運ぶことになります。

- **検索**は正規化した 1 本の文字列への部分一致です。正規化は NFKC →
  小文字化 → カタカナをひらがなへ → 空白と `・` を落とす、の 4 手順。
  **ビルド (`src/heritage_site/search.py`) と画面 (`site/normalize.js`) の
  両方に置いてある**ので、ずれると打った語が当たらなくなります。共通の事例表
  (`tests/normalization.json`) で突き合わせて固定しています
- **ファセットの軸は `meta.json` の `facets` から作ります。**軸の表をサイトに
  持たないので、種別が増えて新しい軸が現れても手を入れずに済みます。語彙が
  空の軸は出しません
- **時代の並びは西暦の中央値**で決めます (年代表をハードコードしない)。西暦を
  持たない値は年代順の後ろへ回します — 年代の分からない値に位置を与えれば、
  それは推測になります
- **座標は地図に置けるものだけ**入れます。欠けている行と日本の外周から外れた行は
  `null` にして、一覧が「地図に位置がない」と示します (黙って落とさない)

### 地図

タイルは**地理院タイル**の淡色を初期表示、ズームは 5〜18 (ADR 0016)。**URL は
`site/map.js` の 1 箇所**にまとめてあります。出典は**地図が見えている間ずっと**
見えるところ (地図の隅) に置き、折りたたみの内側には入れません。ライブラリが作る
表示ではなく `index.html` に書いてあるので、静かに消えれば `tests/test_notices.py`
が落ちます。

**地図ライブラリ (Leaflet) は同梱です。**閲覧者のブラウザが外へ出るのはタイルの
取得だけ、という状態を保ちます。取得元と sha256 は `site/vendor/leaflet/README.md`
にあり、**無改変であること**を `tests/test_vendor.py` が突き合わせます (差し替えは
ファイルごと入れ替えて表を書き直す)。

- **点はマーカーではなく canvas に描きます。**地図に置ける行が 23,482 あり、
  DOM 要素を 1 つずつ置ける数ではありません
- **画面の升目 (56 px) ごとにまとめます** (`site/cluster.js`)。まとめる単位が
  距離ではなく画素なので、縮尺を変えれば同じ密度でまとまり直します。この
  ファイルは DOM にも Leaflet にも触れないので `node` から検査できます
- **地図に出るのは「さがす」で絞った集合そのもの**です。地図側に別の絞り込みを
  持たせません (一覧と地図で見えているものが食い違わないため)。**位置を持たない
  行は件数を地図の上に出して**一覧へ繋ぎます
- **地図が組み立てられなくても一覧は使えます。**地図だけを動的に読み込むので、
  読めなければ地図の場所に理由が出るだけです

## 動かす

```bash
pip install -e '.[dev]'
```

データリポジトリを並べたディレクトリを指してビルドします。

```bash
./scripts/fetch-datasets.sh data-repos   # org から取ってくる (gh が要る)
heritage-site build --data-dir data-repos --out dist
python3 -m http.server -d dist
```

## 検証

```bash
ruff check .
mypy src
pytest -q
```

CI はこれを Python 3.12 / 3.13 / 3.14 で回し、あわせて PR タイトルの
Conventional Commits 形式を検査します (squash merge でタイトルがそのまま main の
コミットメッセージになるため)。

**画面側 (JS) の検査も pytest から回します** — 正規化がビルド側と一致すること、
絞り込みが軸の中で OR・軸をまたいで AND になることを `node` で確かめます。
手元に `node` が無ければその検査だけ飛ばしますが、**CI では飛ばさずに落とします**
(黙って skip すると保証が消えるため)。

## ビルド時の不変条件

サイトはデータリポジトリを読むだけで、直せる立場にありません。検査の役目は
**壊れた状態で黙って配信されるのを止めること**に絞っています。

| 検査 | 破れたとき |
|---|---|
| `schema_version` がサイトの対応版か | 止める |
| 利用日が 45 日より古くないか | 止める (月次更新が止まった) |
| `meta.json` の宣言と実在ファイルが一致するか | 止める |
| `meta.json` の件数と実際の行数が一致するか | 止める |
| 索引に要る項目 (`ledger_id` / `managed_id` / `name` / `url`) が空でないか | 止める |
| 複数の種別に現れる棟が同じ原本 `url` を指すか | 止める |
| 座標の無い行が急増していないか | 止める (台帳の取得漏れを疑う) |
| 日本の外周の外にある座標 | 報せて地図から除く |

止めても配信済みのサイトは残ります (Pages は最後に成功したデプロイを配り続ける)
ので、構造の壊れは止める側に倒しています。逆に**上流データの誤り 1 件で毎月の
反映は止めません**。

## 配信

GitHub Pages。ソースは **GitHub Actions** で、ビルド結果はアーティファクトとして
配ります (生成物はコミットしません)。`.github/workflows/pages.yml` が
main への push・月次・手動実行で走ります。
